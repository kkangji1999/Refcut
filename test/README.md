# 시험

컷을 제대로 나누는지 **숫자로** 확인한다.

레퍼런스 영상을 눈으로 보며 "잘 나온 것 같다" 로 판단하면, 한 컷에서 세 장이
나오거나 스타트 프레임이 한 장 밀린 것을 놓치기 쉽다. 그래서 **컷 위치를 미리
아는 시험용 영상**을 만들어서 채점한다.

## 돌리는 법

```
npm test          # 컷 나누기 + 그림 뽑기 (몇 초면 끝난다)
npm run test:app  # 진짜 앱을 띄워 처음부터 끝까지 (창이 잠깐 떴다 닫힌다)
```

컷 판정(`findCuts` · `choose` · `cutStartIndex`)이나 프레임 시각을 다루는
곳을 건드렸으면 **반드시 돌려보고 올릴 것.**

## 무엇을 보는가

| 파일 | 보는 것 |
|---|---|
| `make-clip.js` | 컷 위치를 아는 시험용 영상을 만든다 (여기가 채점 기준) |
| `cuts.test.js` | 컷 개수와 컷 시작 위치가 맞는가 |
| `grab.test.js` | 저장되는 그림이 '바로 그 장' 인가 |
| `app.e2e.js` | 진짜 앱에서 추출~스타트 프레임까지 이어지는가 |
| `upgrade.e2e.js` | 가짜 CDN 에 진짜로 물어봐서 720p 를 1080p 로 갈아타는가 |
| `fps.e2e.js` | 23.976 영상의 초당 장수를 어긋나지 않게 읽는가 |
| `stream.test.js` | 잡아온 스트림 주소에서 화질을 제대로 읽고 더 높은 화질 후보를 만드는가 |

시험용 영상에는 **컷이 아닌데 컷처럼 보이는 것**들이 일부러 들어 있다.

- 빠르게 흐르는 화면 (휘프팬·핸드헬드)
- 한두 장 번쩍하는 플래시
- 포커스가 흐림 → 또렷으로 넘어가는 컷
- 빠른 줌 (그 앞에는 진짜 컷이 있다 — 걸러내다가 진짜까지 놓치면 안 된다)
- 장 간격이 들쭉날쭉한 판(`--vfr`) — 내려받은 영상 흉내

## 왜 이렇게까지 하나

v26.8.2504 까지 이 영상은 **진짜 컷 7개가 27개로** 잡혔다. 움직임이 큰 컷이
6장마다 새 컷으로 쪼개졌기 때문이다. 눈으로는 "컷이 많네" 정도로만 보여서
오래 남아 있었다. 지금은 7개로 잡히고 컷 시작도 한 장도 밀리지 않는다.

## 주의

`stream.test.js` 는 `main.js` 에서 화질을 읽는 함수들을 같은 방식으로 잘라 온다.
실제로 통신하지는 않는다 — 주소를 읽고 후보를 만드는 부분만 채점한다.

`_core.js` 는 `app/index.html` 에서 계산 함수를 **글자로 잘라 온다**.
손으로 옮겨 적으면 앱과 시험이 조금씩 달라지기 때문이다.
그래서 `index.html` 의 함수 이름이나 그 앞뒤 주석을 바꾸면 시험이 먼저 깨진다.
그때는 `_core.js` 의 잘라오는 자리를 같이 고쳐주면 된다.

`_생성물/` 폴더에 만들어지는 영상과 결과물은 저장소에 올리지 않는다.
